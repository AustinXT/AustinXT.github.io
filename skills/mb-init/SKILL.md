# mb-init · 先把博客边界写清

## 使用与边界

用于新建博客工程、恢复新上下文、修订项目方向；不用于制作首页、批量迁文或上线。

## 顺序

1. 读项目 `CLAUDE.md`、四份 `.42cog/`、状态板与记忆索引。核对 Git、磁盘、参考入口和授权，不从旧仓库启动构建工具。
2. 先生成缺失骨架；已有文件不覆盖、不删。仅在明确授权的范围移动参考原件，目标冲突停止，保留现场与核验记录；不得以初始化幂等为理由重做移动。
3. 起草或建议修订唯一意向；让负责人过目方向，未知条件写未提供。记录作品单位，每创建实际子目录登记实体；不创建 `hi.md`。
4. 意向草稿存在后补当前阶段的工具与精确版本、生态原生配置、最小规则 CI、四步方法。网站栈未定时只锁初始化验证底座，不宣称站点能构建。
5. 用只获得意向书的新上下文验三问：方向、不做、下一步。清单与结构真跑；写状态板与里程碑，记录 remote 与参考备份缺口。

## 失败分流

- 参考原件不可访问：不伪造索引，完成其余初始化，登记缺口。
- 工具缺失：报告；安装待授权，不切换厂商或自动升级。
- 旧原件或目标校验异常：停止该操作，保留现场，不自作回滚或清理。

## 放行

意向三问可回答、规则全过、原件不入新仓库、remote 状态如实登记，可结束初始化。负责人确认方向且跨谱系方法评审实际完成后，进入有界 research；没有外发授权则保留待评审状态，不当作成品制作放行。

产出：意向、配置、方法、核验记录与状态；入口见 `../../README.md`，规则见 `../../scripts/README.md`。
