# mb-evolve · 增积累，不增维护债

## 使用与边界

用于已有人的定标样本后的逐批旧文整理、导航演化、依赖维护及回归；不补造定标或绕过发布权限。

## 顺序

1. 核对原型验收、当前 Git 与本轮获准文章／模块范围；每批先分组，未知权利或私有材料留缺口，不混入可发布批次。
2. 同时看两条线：新增可追溯且有用的内容与发现路径；重复正文、链接债、配置数量、构建依赖及人工维护步骤。没有阅读证据就写未知，不以文章数假装实效。
3. 对照人审样本逐篇整理，维护迁移台账及原 URL 对应；不改旧原件，不一键把全部旧文转为公开稿，不以复制目录保存版本。
4. 每批运行真实构建、元数据、内部链接、旧 URL 与原件忽略回归；新模块目录同步登记。规则失败停该批，其他独立已授权工作可继续。
5. 聚类人改稿与读者实际反馈，提议调整标准或导航；重大技术／域名／结构改变回到 research，方向修改由负责人拍板。
6. 将同类第三次错误沉淀为脚本或一条经验；写状态板、里程碑与下一批建议，不自动安装、上线、提交或推送。

## 意外矩阵

- 没有异地备份：不得把原件清理当优化，先提备份方案；忽略目录和旧 remote 均不证明未提交材料已备份。
- 旧 URL 无法保留：先列受影响链接与替代方案，负责人决定，不默默改 slug 或丢弃映射。
- CI 通过但阅读任务失败：以实效失败记录回 proto；不因规则全绿放大。

## 放行

当前批次规则通过、逐篇来源与人审明确、对链接债和维护成本有记录，且扩大范围获确认，才能继续下一批。平台发布与不可逆清理另行确认；停止某批不意味着删除它。
