# specs — 规约：产出该长什么样

> 与开工手册同属「我立的规矩」：**手册管怎么干，规约管产出该长什么样。**
> 多品牌 / 多产品线时，这里一线一份，与作品区一一对应。

## 子目录

| 目录 | 装什么 |
|---|---|
| [`style/`](style/) | **风格档案**——正例、负例、用词表、定标样本 |

**风格不住在真相源里，住在这里。** `vault/` 管「事实是什么」，规约管「产出该长什么样」——
真相源解决不了「应该是什么」。详见 `style/README.md`。

> **形容词自述不可靠，可靠的是你亲手改掉的每一处。风格不是宣言，是改稿史的压缩。**

## 命名：三种命名法

名字里带什么，取决于你日后**怎么找它**——有的靠序号找，有的靠时间找，有的根本不用找、它自己会来。

| 命名法 | 用于 | 样子 | 为什么 |
|---|---|---|---|
| **流水编号** | 档案（调研 · 计划 · 评审） | `001_kebab-case.md` | 要供人引用，**编号一变引用就断**，所以永不重排 |
| **创建日期** | 过程材料 | `2026-07-16_界面审计.md` | 你只关心它什么时候产生的 |
| **最后更新日期** | 记忆 | `20260728-禁用词.md` | 新的覆盖旧的，更新即改名并同步索引 |

> 记忆和档案的差别只有一条：**记忆是下次自动生效，档案是你去查才生效。**
> 命名方式不同，正因为读取方式不同。

规约类文件（被路径引用的那些）**不编号、不带日期**——稳定性是命根，版本走提交链。

### 三个忽略区的目录名

`_build/` `_tmp/` `_archive/` 不入库，但**目录名有硬格式**——它们靠时间排序，格式一乱就再也理不清：

| 目录 | 只许 | 为什么 |
|---|---|---|
| `_build/` | `YYYYMMDD-HHMMSS/` | 一次构建一个；按天分会撞车（一天出多版就互相覆盖） |
| `_tmp/` `_archive/` | `YYYYMMDD-slug/` | 最后更新日期制 |

三区共同规则：**日期一律打头**（方能一路排序、一眼看出时间）；**均禁裸文件与目录混住**（找起来累，管起来更累）。

## 格式

### 提交信息

前缀 `feat` / `fix` / `docs` / `chore`，后接一句话说清改了什么。

**每次改动附五行标注**（照抄）：

```
Change-By:      human | ai | ai+human
Agent:          用的哪个工具
Model:          哪个模型
Suggested-By:   建议来自谁
Co-authored-by: 姓名 <邮箱>
```

**作者亲手改的那些提交，就是日后喂给 AI 学你风格的唯一真相源**——标注是为了日后分得出哪些提交是人亲手改的。

### 产出格式

作品单位与实际目录实体见 `../.42cog/cog.md`，合格线与验证闭环只在 `../.42cog/intent.md`。原型的 URL 取证、唯一页面、任务与史评分离核查见 [`proto-checklist.md`](proto-checklist.md)；具体样本与任务仍由负责人定标。

- 网站实现采用选定生态的原生目录和配置，不另造一份技术栈映射；当前尚未选型、没有成品模块。
- 创建 `src/` 直接子目录时，实体表增加唯一一行，包含实体名、是什么、具体路径、谁产生、谁是谁的输入，五字段不得为空。
- 已整理文章有一份正文正本，标题、原始日期、整理日期、摘要、状态采用选定生态的原生元数据格式；原文和原 URL 另用指针追溯，不复制正文作版本。
- 迁移台账至少区分原文、原 URL、候选目标、新 URL、取舍、事实时效与人审状态；尚未确定的项标未知，不把候选填成已迁移。
- 整理默认是草稿；已人审、已允许制作和已公开发布分别留可核查记录，不能由 `draft: false` 推定发布授权。
- 旧 URL 要明确保留、映射或不迁移的理由；不能默认丢掉 slug、把所有路径转到首页或改写历史日期。
- `hi.md` 不是必备文件，AI 不代建、不修改。参考原件、第三方素材、凭据和个人数据不进入可提交成品。
- 初始化规则入口为 `python3 -I scripts/check-system.py`；它不判内容真假、阅读实效或线上成功。框架确定后补构建与链接规则，原型由负责人定标。
