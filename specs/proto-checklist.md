# 原型核查清单

> AI 起草的首轮方法摘要评审后执行清单；处理证据见 `../docs/reviews/005_glm-method-review.md`。规则承接既有约束，具体样本与任务待负责人改定。本清单不代替人的文稿/阅读样本，不是安装、制作或上线批准。

## 一、进入与状态

- 方向、技术、首篇与整理范围确认以 `../.42cog/intent.md`、`../docs/research/002_blog-direction-decision.md` 为正本。
- 原文与第三方素材许可、负责人定标、方法意见处置、依赖获取与制作授权分别记录，不从其中一项推导其他项。
- 研究、AI 草稿、人改定样本、规则通过、人验收、允许公开发布分别标状态。尚未执行的项必须为“未验证”，不能填“通过”。
- 此阶段只做获准的单篇阅读闭环；原件只读、唯一正文、命名与迁移台账按本目录 `README.md`。

## 二、旧 URL 证据与冻结

迁移台账逐篇列：候选旧路径、证据入口、观察日期、证据类型、候选目标、置信边界、授权与确认状态。正文不在此复制。

可用证据分开记录：

1. **既有本地证据**：原文元数据、历史提交、已登记配置与生成物。生成页存在或自指 canonical 不证明当时上线，旧 Git 文件提交日期不替代原始发布日期。
2. **公开线上证据**：仅针对已登记旧站及候选路径作有界只读访问，记录响应状态、跳转目标、canonical 与访问日期；公开 sitemap 可补证，查询不到则标未核实。不登录后台、不扩大成全站抓取，不把私人日志当公开材料。
3. **需权限的证据**：日志、私有发布记录或后台导出，由负责人自行提供已脱敏证据；不索要/读取凭据、不自行登录。仅记录必要结论与来源指针，含个人数据的原始日志不入库。

本地原型允许使用明确标为“待冻结”的候选路径；线上证据缺失不阻止已授权的离线样本，但必须列缺口。发布或替换旧站前，由负责人明确冻结目标主机、逐篇路径及未迁路径去向；本地候选不能无声变成线上既定事实。

## 三、唯一页面与跳转规则

框架确定后的检查须覆盖：

- 每篇整理稿只有一个预期正文目标 URL，页面 canonical 指向该目标。标题调整不自动改变冻结路径。
- 其他历史地址不得再渲染同文全文并声明另一个自指 canonical；只作为兼容入口，检查最终目标正确、无循环、无跨主机误指。
- 中文与百分号编码先按明确规则归一核查，避免同一路径重复生成；比较路径时不把不同主机混为同一 URL。
- HTML meta refresh 可以作为静态兼容方案，必须标为 HTML 客户端跳转；只有实际 HTTP 响应证明 301 时才记录 HTTP 301。对托管平台不支持的服务器规则，不先承诺。
- 分别记录本地产物检查与线上响应检查；本地通过不等于线上通过。跨主机时，新站规则不替代旧主机控制权与授权。
- 同主机替换之前，未迁文章已有保留/归档/明确不迁移的逐条处理；不得默认全部转首页或删除。上线授权另取。

以上是原型检查的要求，当前没有新站产物或相应构建/链接检测脚本，不标为实现通过。

## 四、单篇阅读与查找任务

评分锚点、三维与总分唯一正本为 `../.42cog/intent.md`，不在此复制或删掉维度。AI 按判据检查，负责人做实效验收；原型尚未运行时不填实际得分。

| 任务 | 起点与动作 | 可观察的失败 | 本轮边界 |
|---|---|---|---|
| 首页到文章 | 从首页找到获选文章标题并进入 | 无入口、错稿、标题与目标不匹配、正文不能读 | 手机与桌面各记录一次真实结果 |
| 按主题查找 | 不给文章直链；从首页识别获选文章的主题入口，再找到同一篇 | 主题入口缺失/看不见、分类无法理解、主题列表不含目标、链接错误 | 单篇可验证导航闭环；不能证明多篇中找文有效率 |
| 长文目录与返回 | 从文章目录跳到指定小节，再返回文章列表 | 锚点错位、目标不可见、目录失效、无法回列表 | 目标小节由负责人指定；不用 AI 推定可读 |
| 继续阅读 | 至少第二篇加入后，从一篇到另一相关篇 | 相关入口缺失、指错、关联不成立 | 本轮单篇标“不适用”；不伪造相关文章 |

主题入口可以是同一阅读模块中的小列表，不预造全站栏目或批量分类。定标记录包含设备、任务目标、观察结果、负责人反馈与修改指针；可记录耗时，但未由负责人确定的时间阈值不能擅自成为合格线。单篇导航通过不支持扩大迁移前跳过多篇复测。

## 五、历史、引用与新增解释的核对

迁移台账或人审记录逐项标明，指向一份新正文与一份原件，不再存正文副本：

| 内容类型 | 规则核查 | 人审 |
|---|---|---|
| 原始日期与来源 | 原始日期同已核原文元数据；来源/原文指针存在；整理日期和状态另列 | 日期冲突、来源事实与公开范围由负责人确认，不用文件名或最近提交替代 |
| 声明原样保留或直接引用的段落 | 原文段落指针可定位；只对这些段落做比对，归一化规则限于预先声明的排版差异，不吞掉数字、否定词或语义标点 | 引用出处、引用范围与第三方许可确认 |
| 独立改写的历史内容 | 标为历史整理，指向所依据段落；不要求全文 diff 为空 | 核对事实、时效、数字/分母及推论，没有把旧结论洗成当前事实 |
| 新增解释/实践 | 与历史内容明确分区并标整理时间；缺证据不能装作本人新经历 | 由负责人确认观点、经历与本人声音；AI 不代认 |
| 取舍与省略 | 记省略范围和理由的指针，不改旧原件 | 确认未扭曲原意，未经确认项仍为草稿 |

规则不能证明语义保真、版权或本人声音；负责人应针对上述边界逐项确认，而非仅通读觉得顺。检查脚本及其反例回归在获准原型实现时补齐；方法清单写全不等于程序已跑过或稿件已人审。
