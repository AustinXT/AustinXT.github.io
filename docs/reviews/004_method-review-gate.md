### 候补入口的只读核查结论

- `dsh-headless/lib/startup.js:20–39` 仅支持 task 位置参数，无 stdin/提示词文件选项。Shell 展开文件正文后作为参数传入仍是“提示词进入命令行”，不使用这种写法。
- 本地 JS 启动器可先读文件/stdin，在进程内设置 argv 后 import 入口；这可以解决 OS 命令行暴露，但单独不能解决工具与上下文隔离，不宣称已实现或验证。
- 发行 `dsh-base/cordis.patch.yml:210–248,292–340,367–418,424–432` 存在文件、shell、子代理、workflow、web 等多个工具注册者，工具 registry 无 none 模式。禁单个 tool 插件或 restrict 继承工具不能证明全部禁用；需要逐插件覆盖并验证，无现成总开关。
- `dsh-headless/cordis.patch.yml:7–20` 默认 persona 带 cwd，工具 mode 可受环境覆盖。`lib/profile-boot-DG5t9aNs.js:140–176` 启动会准备并重写 profile root，同时加载 profile/home 补丁；`--patch` 不阻止这些前置行为。因此本次不直接启动，也不自动改写用户 profile 来强行通过。
- 发行默认模型为 `deepseek-official / deepseek-v4-flash`，可被个人设置覆盖；不是已验证的当前选中模型。正常启动不自动 pnpm install，但可能初始化配置或修复链接，不能把“不会安装”当作“不改现有状态”。
- 以上只查已安装发行源码及默认 bundle，未读取个人配置、凭据或用户 profile。源码根由本机 executable 解析所得；没有外发这些源码或项目资料。
