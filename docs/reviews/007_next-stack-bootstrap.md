## 实际失败与修正

1. registry 最新 TypeScript 7 系超出 `@typescript-eslint/parser` 支持范围，安装前改选兼容稳定 5 系；不是默认追所有 latest。
2. 首次安装有三条 peer override 告警；`npm ls` 实际退出 1，确认 ESLint 10 与 import／jsx-a11y／react 插件的 peer 范围冲突。改选最新兼容 9 系，重新安装并 `npm ci` 验证；不使用 force 或 legacy-peer-deps 绕过。
3. 首次 lint 退出 0 但有一条匿名 PostCSS 导出告警；配置改为具名变量，lint 加零告警门槛，复验通过。
4. Next 第一次构建自动补 `allowJs` 并维护 `next-env.d.ts`，保留原生工具行为；类型入口与构建缓存忽略，不手改生成文件。
5. 新检查器夹具全绿后，实际作品页首次检查失败：空态文案未出现契约中的“待确认／未迁入正文”。将作品文案明确为待确认后重建，实际导出通过；不把仅夹具通过报成实际通过。
6. `git diff --check` 发现研究卡尾部空行，修正后复验；没有重排历史决策。
7. Chrome DevTools 仍无 DevToolsActivePort；未改浏览器配置或安装驱动。通过实际本地 HTTP 请求验证八路由与十个被引用框架资源，不能替代浏览器点击、渲染或手机体验。
