## 目录实现

- 一个 catch-all 路由 `app/essays/[...path]/` 承接文章页、年份页和年份分页；理由见「实际失败」第 2 条。
- `/essays/` 的时间线列全部非空年份，文章条目放在年份页。年份页每页上限 100 篇，超过才分页；首页随笔速览列最新 5 篇。
- 目录类链接都不预取。文章页按 h2 生成目录，h2/h3 都带锚点，重名的锚点加序号。

## 实际失败与处置

1. **误把一个目录从 Git 暂存区移除。** 本想只删工作区文件，误用了 `git rm --cached`。立即 `git reset` 还原，复查暂存区为 0 个文件；没有提交。
2. **单独的分页路由让构建失败。** 报错原文：`returned an empty array from "generateStaticParams()". With "output: export", at least one route must be generated`。没有分页时这个路由就没有参数，所以改成一个 catch-all 路由。由此也确认：所有文章都是草稿时，静态导出会失败（008 记录里列为「未验证」的一项）。
3. **检查器把固定路由当成了文章。** 文章路由的正则也匹配 `categories`、`tags`。改为先排除固定路由。
4. **新测试类插错了位置。** 它插进了既有测试类的中间，导致 6 个既有测试在「上限 = 2」的设置下运行。移到正确位置后重跑。
5. **两个反例失败的原因不对。** 「同一篇列两次」被「年份不对」先拦下，「年份列表在时间线外」被标签不平衡先拦下。改准后逐个打印失败原因核对。
6. **突变验证抓出两处测试漏洞。** 删掉「路由形状」和「条目日期属于该年」两条规则后，测试仍全绿，因为反例同时触发了别的规则。改为只触发目标规则的反例后复验，全部被抓到。
7. **YAML 把 `slug: 2019` 读成数字。** 结果被更早的规则拒绝，没测到「slug 须含字母」这条。测试改用带引号的写法。
