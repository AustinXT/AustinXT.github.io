# exp001 · 旧 URL 证据小实验

## 假设

文章文件名可能不足以还原旧 URL；`public/` 可能混有多次构建遗留页面，不能单凭文件存在认定现行地址或已公开。

## 做法与复现

2026-10-09，在项目根运行：

```bash
python3 -I docs/experiments/exp001-url-evidence/inspect_urls.py vault/raw/05blog
```

仅解析三个获选候选的正文哈希、六个已知生成页的 canonical / refresh 与一份 sitemap。输入原件身份见 `../../../.42cog/meta.md`；脚本不执行旧代码、不读取草稿、凭据或个人记录，不构建、不写输入目录、不访问网络。结果不是线上响应检查。

## 观察

三个候选均有两种本地路径，且两页各自声明 canonical，没有 meta refresh；站点地图只列标题路径：

| 原文文件 stem | 站点地图中的路径（解码后） | 另一个已有生成路径 |
|---|---|---|
| `2019-12-23-卡片学习心得` | `/卡片大法/` | `/2019-12-23-卡片学习心得/` |
| `2019-08-04-解读统计数字四步骤` | `/解读统计数字的行动清单/` | `/2019-08-04-解读统计数字四步骤/` |
| `2018-01-07-quickenter-new-academic-realm` | `/如何快速了解一个学术领域/` | `/2018-01-07-quickenter-new-academic-realm/` |

该 sitemap 共 131 条 loc，包含非文章条目，不能用它推导文章总数。canonical 的主机是配置中的历史 GitHub Pages 主机；旧 `static/CNAME` 另登记了域名，不能把两者混作已验证的当前服务地址。

## 结论与边界

- 假设得到支持：候选文件名不是唯一 URL 依据。迁移台账至少要登记 sitemap 路径与历史文件名路径。
- 建议已迁文章优先保留 sitemap 所示标题路径，文件名路径作兼容候选；这是本地证据下的建议，线上 canonical、旧发布版本及读者历史链接尚未核查。
- 这些并存页面与残留生成物相符，但没有各次构建日志，不能认定哪个页面何时上线，不能把两个自指 canonical 误写成已有重定向。
- 时间边界：2026-10-09 的本地快照；规模边界：3 篇、6 个生成页、1 份 sitemap。不能推广成所有旧文都使用标题路径。
- 没有证明新框架可构建、HTTP 301 可用、域名可控或手机阅读通过。选型取舍正本见 `../../research/002_blog-direction-decision.md`。
