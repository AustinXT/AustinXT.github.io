# 有界核查任务

本轮单执行者，不启动多代理编排；以下角色用于分离证据与推断，不冒充独立模型评审。

| 角色 | 逐条核查 | 证据格式 | 输出上限与判断 |
|---|---|---|---|
| 现网识别 | 首页及随笔页实际引用什么；包内是否明示 Next/React 版本；CSS 与图标是否有组合特征 | `sources.md` 的 E 编号、原始 `file:line`、URL 与版本标识 | 500 字；首选借鉴阅读组织，备选研究现栈；列三个误判风险 |
| 历史反证 | “现网 Jekyll”能否被现有资源推翻；旧原文是否可用；是否能确定迁移时间 | HTTP 状态、现网资源对照、二手与一手分级 | 300 字；无证据就报未知 |
| 托管反证 | Cloudflare 是否仅说明代理；Next/v0 是否足以证明 Vercel；RSC 是否足以证明 SSR | 原始响应头、DNS、官方 static export 文档 | 300 字；不得补猜源站与构建模式 |

## 冒烟与意外矩阵

- 先首页冒烟，拿到直接资源引用后才扩展随笔页及被引用资源，未全站抓取。
- 如果网页正文提取不保留资源标签，那么用 curl 获取公开 HTML。
- 如果 Python 直连返回 403，那么改用已成功 curl；不绕过认证或访问非公开内容。
- 如果浏览器不能连接，那么保留静态证据，不声称页面交互、运行态版本或视觉通过。
- 如果官方输出示例与压缩 CSS 文本不完全相同，那么检查语义等价层声明，不把字面断言失败直接当成框架不存在。
- 如果没有仓库、锁文件、部署配置，那么停止在外部可观测层，不无限搜索后台。

三个主要风险：历史文章误作现网、生成器标签误作完整开发流程、边缘服务误作源站托管。处置见 `gap.md`。
