# 取舍卡 · 正文 MD：浏览器解析还是发布前编译

> 2026-10-10。负责人提问：随笔和大部分作品详情以 MD 存在项目里，网页显示 HTML；是网页直接解析 MD，还是发布前编译成 HTML？文章会很多，要一直加载流畅。此题参考 yangzhiping.com。
> 最后一栏「需要你拍板的地方」由负责人填写。2026-10-10 负责人回复「brotli 是什么，其他的都按你的建议」：第 1–5、7 项按建议确认。在解释 brotli 之后，负责人选第 6 项为「必要条件」，第 8 项为「放行第一批，用占位文章跑通」。

## 候选

- **B 浏览器解析**：页面下发 `.md` 原文和解析器，在读者的浏览器里转成 HTML。
- **A 发布前编译**：构建时把 `.md` 转成 HTML 再导出静态文件，读者拿到的就是 HTML。A 有三种写法：
  - **A2**：普通页面路由。构建时读 `.md`，用 unified 编译成 HTML，由 Server Component 输出。
  - **A2-R**：同样的编译，但文章页改由 Route Handler 直接输出一份纯 HTML 文件，不经 React 页面。
  - **A1**：`@next/mdx`，把 `.md` 当作模块交给打包器编译。

## 这次不可妥协的几条

下文称为命门 1–3。以下三条是 AI 草稿，待负责人确认（拍板第 1 项）。

1. MD 是唯一正文正本，HTML 只是可再生的构建产物。
2. 不执行 JS，首个 HTML 响应里就有完整正文。
3. 单篇加载成本与文章总数无关，目录页条目数有上界。

## 我选择什么

**选 A2。**

- 构建时用 gray-matter 读 front matter，用 unified 链编译 `.md`：remark-parse → remark-gfm → remark-rehype → rehype-stringify，公式与代码高亮按需再加。
- 由 Server Component 静态导出。
- 目录页必须有条目上限。拆法待拍板，建议按年份拆页。

## 我放弃什么

- **放弃 B。**
- **A2-R 留作备选。** 它最轻，但只能另写一套布局模板。
- **暂不用 A1 和内容层库。**
- **不照搬参照站的目录做法。** 参照站是「年份按钮 + 全量索引随页下发」。

## 支持它的最强依据

exp003：

- 文章数从 100 涨到 6000，同一篇详情页始终是 65,760 B，引用的 7 个 JS 文件完全相同；
- 3000 篇全量构建 12.4 秒；
- 分页目录恒定在 4.2 KB（gzip），全量列表到 3000 篇时涨到 167.6 KB。

B 做不到命门 2：正文不在首个 HTML 里，每页还要多带 13–44 KB（gzip）的解析器。

## 反对它的最强依据

**A2 的问题：** Next 的页面路由会在 HTML 里再嵌一份 RSC 数据，正文因此在页面里有两份。

- 参照站这份数据占页面的 58–59%，exp003 占 55%。参照站的正文是 React 元素树，A2 插的是 HTML 字符串，但两种写法在页面路由下都会被嵌进这份数据，所以参照站的数字也能用来衡量 A2。
- 参照站一篇 5343 字的文章：两份正文相距超过 32 KB，gzip 去不掉重复，重复部分要再付 92%；brotli 只再付 34%。
- exp003 里最短的那篇（1814 字），这份内嵌数据也让页面重 46–48%。
- `out/` 里每篇文章有 5 个文件。

**A2-R 能消掉这些：** 同一篇文章，gzip 后 12,079 B 对 A2 的 25,258 B，没有脚本，每篇 1 个文件。

**这条攻击的是「用哪种写法发布」，不是「要不要发布前编译」。** B 同样跑在 Next 上，还要多带解析器，所以「A 优于 B」不变。

仍然选 A2，理由有三：

- 布局与组件只有一份；
- 与已选的 Next 页面写法一致；
- 托管支持 brotli 时，代价可以接受。

若托管只能给 gzip，或真机加载达不到要求，就改用 A2-R。

## 仍未补齐的缺口

**托管侧的压缩方式（brotli / zstd）与文件数上限，正是这两项决定 A2 的双份代价能不能接受。**

2026-10-10 补查了压缩方式：GitHub Pages 只给 gzip。负责人现有的 `blog.nightvoyager.top` 和 `pages.github.com` 两个站点，浏览器声明支持 `br, gzip`，返回的都是 `content-encoding: gzip`（`sources.md` O9）。文件数上限仍未核实。

## 不需拍板的默认做法（你反对再改）

- 目录、标签、年份页的链接设 `prefetch={false}`，或只在悬停时预取（O2 对大列表的建议）。目录有上界后，预取量与总篇数无关，所以这只是流畅性优化。一屏 20 条链接，按均值约 11 KB 一篇估算，未实测。
- 在 `globals.css` 里用 `@source not` 排除正文目录，避免 Tailwind 扫正文。exp003 里它扫了正文与依赖目录，CSS 从 8.7 KB 膨胀到 79 KB。
- 摘要、简介等字段也走同一条编译管线，避免像参照站那样漏出 `**`。
- 默认不开原生 HTML。将来要开时，再评估 rehype-raw 和 rehype-sanitize 对公式、高亮和标题锚点的影响。
